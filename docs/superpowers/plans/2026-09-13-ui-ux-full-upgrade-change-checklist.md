# InkEdge 页面 UI/UX 全面升级改动清单

本文是对“页面 UI/UX 全面升级计划”的纯清单版，只列要改哪些内容，不包含代码片段、命令或实现细节。

## 一、全局视觉体系

- [ ] 统一主色、辅助色、文字色、边框色、背景色和状态色。
- [ ] 统一深色主题和浅色主题下的按钮、卡片、输入框、边框和阴影观感。
- [ ] 统一卡片圆角，普通卡片和控件保持克制，不使用过大的圆角。
- [ ] 统一主按钮、次按钮、文字链接、禁用按钮、加载按钮的视觉状态。
- [ ] 统一输入框、下拉框、文本框的高度、边框、聚焦状态和错误提示。
- [ ] 统一空态、成功提示、错误提示、加载提示的样式。
- [ ] 减少 styles.css、app-apple.css、account.css 之间互相覆盖和风格不一致的问题。
- [ ] 保留现有深浅主题切换能力。
- [ ] 避免页面整体变成单一色调，蓝绿色作为主色，其他颜色只用于状态和区分层级。

## 二、主应用整体结构

- [ ] 优化顶部品牌区，让“墨锋 InkEdge”和当前登录状态更清楚。
- [ ] 统一顶部操作按钮的样式，包括登录、学习档案、主题切换和清空页面。
- [ ] 优化左侧导航，使当前所在功能更明显。
- [ ] 优化左侧导航在移动端的排列方式，避免挤压和横向滚动。
- [ ] 修正导航兜底逻辑，避免页面默认跳到不该进入的功能页。
- [ ] 统一主内容区宽度、留白和页面分区间距。
- [ ] 让页面第一屏直接出现实际可操作入口，而不是大段说明。

## 三、总览页

- [ ] 重做总览页的功能入口卡片。
- [ ] 保留并突出主要入口：我还没写、我写完了、素材库、训练计划、成长。
- [ ] 增加学习档案入口，但不要抢占主要写作功能入口的位置。
- [ ] 每张入口卡片只保留短标题、短说明和明确按钮。
- [ ] 删除过期占位文案和无关功能提示。
- [ ] 让入口卡片在桌面端整齐排列，在移动端单列或双列显示。
- [ ] 空数据时显示短提示，不显示大段解释。

## 四、“我还没写”写作引导

- [ ] 将输入区拆成清楚的第一步：题目、年级、文体、真实素材。
- [ ] 让“真实素材”输入框在视觉上更重要，提醒用户输入自己的经历。
- [ ] 将立意方向、素材追问、提纲树、段落提示、段落草稿分成不同区域。
- [ ] 每个立意方向卡片显示为什么扣题、怎样使用素材、写作路径和风险提醒。
- [ ] 素材追问下方保留用户回答框，回答框位置要和问题对应。
- [ ] 提纲树要有清楚层级，能看出开头、经过、变化和结尾。
- [ ] 段落提示要说明每一段写什么、写哪些细节、怎样检查。
- [ ] 每个段落提示下保留作文输入框，方便学生直接写。
- [ ] “我写完了”按钮要清楚表示会合并段落并进入作文体检。
- [ ] 请求失败时不要清空已经生成的可用结果。

## 五、“我写完了”作文体检

- [ ] 将作文体检报告拆成概览、优先问题、详细建议和下一步操作。
- [ ] 优先问题要醒目显示，让用户先知道最该改哪里。
- [ ] 每个问题卡片包含问题表现、原因和建议动作。
- [ ] 长作文诊断结果要分段展示，避免堆成一整块文字。
- [ ] 错误提示要使用中文可理解文案，不暴露内部异常。
- [ ] 单独粘贴草稿和从“我还没写”合并草稿进入，都要保持路径清楚。

## 六、局部修改

- [ ] 将局部修改结果拆成问题、改法、示范句三个部分。
- [ ] 用户输入修改目标的位置要更明显。
- [ ] 示例句和建议要区别展示，避免用户误以为必须照抄。
- [ ] 移动端下三栏内容改为单列展示。
- [ ] 失败时保留原输入和已有结果。

## 七、素材库

- [ ] 将素材库条目改成更清楚的素材卡片。
- [ ] 每张素材卡显示素材主题、简短摘要、可用题目方向和标签。
- [ ] 保存素材后的反馈要明确告诉用户保存成功。
- [ ] 空素材库时给出短提示，引导用户先保存一条真实经历。
- [ ] 素材库和“我还没写”的素材输入在视觉和文案上保持一致。

## 八、7 天训练计划工作台

- [ ] 优化训练计划页顶部，让“7 天单篇作文训练”和当前状态更清楚。
- [ ] “生成 7 天计划”按钮保持单独入口，不恢复上方旧信息表单。
- [ ] 阶段时间线显示 Day 1 到 Day 7，并明确当前阶段。
- [ ] 当前阶段、阶段结果、下一步操作分成清楚区域。
- [ ] Day 1 立意方向区域突出选择动作。
- [ ] Day 2 素材追问区域保证问题和回答框一一对应。
- [ ] Day 3 提纲树使用清楚的树状层级。
- [ ] Day 4 段落提示用卡片展示每段写作任务。
- [ ] Day 5 段落草稿输入框要足够醒目和易写。
- [ ] Day 6 诊断结果要突出优先修改问题。
- [ ] Day 7 复盘结果要显示本次学到什么、下次练什么。
- [ ] 不能再出现 14 天、30 天、考试冲刺等无关预填项。
- [ ] 训练计划页面移动端不能横向溢出。

## 九、成长地图与能力诊断

- [ ] 将成长功能分成能力阶段、当前重点、练习记录三个区域。
- [ ] 能力诊断结果要用清楚卡片展示，不要只输出普通段落。
- [ ] 成长地图要显示用户最近的变化，而不是抽象口号。
- [ ] 暂未生成数据时显示短空态。
- [ ] 学生和家长都能看懂当前该继续练什么。

## 十、学习档案和账户页

- [ ] 学习档案入口文案统一，不再使用“返回检测页”这类过期表达。
- [ ] 账户页顶部和主应用顶部风格对齐。
- [ ] 账户概览、基本信息、算力记录、充值说明、管理员区域层级更清楚。
- [ ] 账户页卡片圆角、按钮、边框、阴影与主应用统一。
- [ ] 移动端账户页信息不挤压、不横向滚动。
- [ ] 管理员区域保持清楚边界，避免普通用户误解。

## 十一、首页入口

- [ ] 首页入口视觉和主应用品牌保持一致。
- [ ] 首页第一屏只保留进入应用的核心入口和必要品牌信息。
- [ ] 减少独立样式体系，避免首页和应用内部像两个产品。
- [ ] 移动端首页按钮可点击区域足够大。

## 十二、加载态、错误态和空态

- [ ] 所有主要生成按钮都要有加载状态。
- [ ] 加载时防止用户重复点击。
- [ ] 请求失败时显示清楚原因和可继续操作的提示。
- [ ] 请求失败不覆盖已有可用结果。
- [ ] 没有数据时显示短空态，引导下一步操作。
- [ ] 成功状态和错误状态使用不同颜色，但都要克制。

## 十三、移动端体验

- [ ] 主应用、训练计划页、账户页都要检查移动端布局。
- [ ] 表单、阶段卡、结果卡、按钮在手机宽度下不溢出。
- [ ] 左侧导航在移动端变成更适合触控的布局。
- [ ] 长文本结果可阅读，不遮挡按钮。
- [ ] 按钮和输入框点击区域足够大。
- [ ] 页面不出现不必要的横向滚动。

## 十四、可访问性和可读性

- [ ] 所有可点击元素有清楚的聚焦状态。
- [ ] 主要文本和背景对比度足够。
- [ ] 按钮文案能说明动作结果。
- [ ] 状态提示能被屏幕阅读器识别。
- [ ] 当前阶段、当前导航、当前选择要有视觉和语义提示。
- [ ] 不使用只靠颜色区分的关键信息。

## 十五、测试与验收

- [ ] 增加静态 UI 检查，防止旧占位文案和旧入口回流。
- [ ] 增加主流程浏览器冒烟，覆盖桌面和移动端。
- [ ] 保留并更新短期写作指导前端测试。
- [ ] 保留并更新 7 天训练计划前端测试。
- [ ] 扩展主题测试，检查深色和浅色主题下的关键组件。
- [ ] 完成后生成 UI/UX 冒烟测试报告。
- [ ] 测试报告保存到 docs/reports 目录。

## 十六、建议执行顺序

- [ ] 第一步：建立基线检查，记录当前主要 UI 问题。
- [ ] 第二步：统一颜色、圆角、按钮、卡片、输入框等基础规则。
- [ ] 第三步：升级主应用骨架和导航。
- [ ] 第四步：升级总览页入口。
- [ ] 第五步：升级“我还没写”完整写作引导路径。
- [ ] 第六步：升级作文体检和局部修改结果。
- [ ] 第七步：升级素材库、成长地图、学习档案。
- [ ] 第八步：升级 7 天训练计划工作台。
- [ ] 第九步：统一加载态、错误态和空态。
- [ ] 第十步：完成移动端、可访问性和冒烟测试。

## 十七、暂不做的事

- [ ] 不重写后端接口。
- [ ] 不引入新的前端框架。
- [ ] 不改变 DeepSeek 调用逻辑。
- [ ] 不新增 14 天、30 天或考试冲刺计划。
- [ ] 不做纯宣传页。
- [ ] 不把功能说明写成大段教学文案。

置信度：0.89

依据：本清单根据已生成的 UI/UX 全面升级计划整理，并对当前项目的主应用、训练计划页、账户页、首页入口、样式文件和测试范围进行了归纳。它只描述要改哪些内容，不包含实现代码，因此适合用于需求确认和开发前核对。主要不确定性在于实际执行时可能会发现部分旧样式互相覆盖，需要在开发阶段通过浏览器测试进一步确认。
