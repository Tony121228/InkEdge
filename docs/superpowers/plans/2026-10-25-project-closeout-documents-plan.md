4. 使用当前源码、页面、API 路由、部署配置、测试脚本和目录统计交叉核验，避免照抄过期描述。

## 编写原则

- 不覆盖现有文档和历史报告。
- 将“代码已实现”“测试已通过”“线上已验证”分别标注。
- 不把已经移除的算力计费、临时 IP 额度和旧充值说明写成现有功能。
- 微信收款码按当前实现保留，但不解释为已启用的收费系统。
- 参考对照真实生成质量写明已完成提示词与上下文改进；若缺少最新真实模型验收证据，则标为后续运营观察项，而不是未完成功能。
- 迭代数据只使用仓库中可验证的数据；无法证明的用户量、调用量、准确率、收入等不虚构。
- 三份文档均在末尾给出置信度评估。

## 验证方式

- 检查三份文档路径、标题、章节和内部引用。
- 重新枚举当前页面、API、测试脚本、报告数量，为迭代数据提供可复核统计。
- 对关键结论逐项对应到最新报告或当前源码。
- 文档完成后执行敏感信息检查，确保不写入 SMTP 密码、API Key、验证码、用户隐私或其他 Secret。

## 置信度评估

计划可执行性：0.97。主要不确定性是仓库没有真实业务运营指标，因此迭代数据报告将以开发过程、功能、测试和文档统计为主，不虚构生产运营数据。
