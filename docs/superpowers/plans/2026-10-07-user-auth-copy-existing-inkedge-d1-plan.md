# 完整复现参考项目用户登录系统计划

## 1. 用户目标

完整复现 `D:/tony/“你像AI吗”文本检测反测站` 的用户登录/注册界面和现有代码逻辑，并直接使用 Cloudflare 上已存在的 InkEdge D1，不创建第二个同用途数据库。

## 2. 已确认事实

- Cloudflare 账户中存在 `inkedge-state`，与当前项目 `wrangler.jsonc` 的 `APP_STATE_DB` 绑定一致。
- Cloudflare 账户中还存在参考项目的 `ai-text-detector-state`，该库属于另一个项目，不应被墨锋直接复用。
- `inkedge-state` 可远程读取，已有 `app_state_records`、`security_rate_limits` 和现有用户/作文集合记录。
- 当前项目的 `public/account.js` 与参考项目的 `public/account.js` 完全一致。
- 当前项目账号页的登录/注册弹窗结构与参考项目一致。
- 当前项目主工作台的邮箱验证码接口和后端认证接口已经存在。

## 3. 本轮已完成

- 主工作台登录入口改为参考项目的双行账号按钮。
- 复制参考项目的游客/登录状态显示语义。
- 移除空的 vendor auth 占位脚本，保留原生邮箱验证码流程。
- 修正游客 API 返回 `authenticated: false` 时的前端判断。
- 账号页同步修正游客状态，避免把游客占位用户当成已登录账号。
- 使用真实浏览器验证工作台和账号页登录弹窗。

## 4. 后续实现边界

### 4.1 继续沿用参考项目的单库存储方式

不新增 `AUTH_STATE_DB`，直接使用现有 `APP_STATE_DB` / `inkedge-state`。状态集合继续由当前项目的 `app_state_records` 保存，验证码尝试计数继续由 `security_rate_limits` 保存。这样可以保持参考项目的存储方式，也避免账号数据与作文会话之间出现跨 D1 一致性问题。

### 4.2 不复制参考项目的生产数据

参考项目的 `ai-text-detector-state` 只作为代码和结构参考，不读取或迁移其中用户数据。当前 `inkedge-state` 的既有数据不做删除、清空或结构重建；后续迁移只允许追加兼容字段，并先做远端备份或导出核对。

### 4.3 完整验收清单

1. 游客打开工作台，看到“游客 / 点击登录”。
2. 点击账号按钮，看到参考项目同样的登录/注册弹窗。
3. 邮箱格式错误、验证码为空、验证码错误和验证码过期均显示接口错误。
4. 真实验证码登录成功后，账号按钮显示用户名和算力。
5. 新邮箱首次验证创建账号并领取注册赠送算力。
6. 账号页显示用户资料、算力余额和流水。
7. 退出登录后工作台和账号页都恢复游客状态。
8. Cloudflare Worker 生产环境使用 `Secure` HttpOnly Cookie。
9. 账号、验证码、会话、算力流水和作文业务仍从同一个 `inkedge-state` D1 正确读取。
