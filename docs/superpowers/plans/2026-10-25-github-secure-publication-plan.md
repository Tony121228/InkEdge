# 墨锋 InkEdge GitHub 安全发布计划

日期：2026-10-25  
目标仓库：`https://github.com/Tony121228/InkEdge`  
仓库可见性：公开  
目标分支：`main`

## 一、发布前审查结论

已完成只读检查：

- 本地 `main` 与 `origin/main` 当前提交一致，尚未包含工作区中的结项版本。
- Git 远程读取正常；`git push --dry-run origin main` 正常。
- GitHub CLI 未安装，但不影响使用 Git 和现有凭据推送。
- `.env` 已被 `.gitignore` 排除，当前未被 Git 跟踪，公开仓库当前分支也不存在该文件。
- `docs/SMTP配置.txt` 已被 `.gitignore` 排除，当前未被 Git 跟踪，公开仓库当前分支也不存在该文件。
- 本地状态、D1 运行数据、Wrangler 临时目录、`node_modules`、输出截图和训练日志已排除。
- 工作区文本扫描未发现 OpenAI 风格 API Key、GitHub Token、Google Key、AWS Key或私钥正文。
- 测试代码中存在 `test-key`、测试 Secret 等固定测试值，它们不是生产凭据，可以提交。

发现的公开风险：

- 当前公开仓库已经跟踪微信收款码 JPG 和 SVG。
- 当前公开仓库的 `server.js` 和 `wrangler.jsonc` 已包含真实管理员邮箱。
- `README_AGENT_HANDOFF.md` 中也包含该管理员邮箱说明。
- `docs/` 当前整体被忽略，因此新生成的结项文档默认不会上传。
- `.superpowers/` 和部署脚本备份当前未忽略，不适合作为正式源码上传。

## 二、准备修改

1. 调整 `.gitignore`：
   - 继续忽略 `.env`、`.env.*`、`docs/SMTP配置.txt`、`data/`、`.wrangler/`、`node_modules/`、输出目录和训练日志。
   - 新增忽略 `.superpowers/`、`*.backup-*` 和真实微信收款码文件。
   - 允许普通 `docs/` 文档上传，但继续单独排除 SMTP 配置文件。

2. 脱敏源码与文档：
   - 删除 `server.js` 中的真实默认管理员邮箱，只从 `ADMIN_EMAILS` 环境变量读取。
   - 删除 `wrangler.jsonc` 中的真实管理员邮箱，不在公开配置中设置管理员名单。
   - 将交接文档中的真实管理员邮箱替换为环境变量说明。
   - `.env.example` 只保留示例邮箱和空凭据。

3. 保护收款码：
   - 将真实 JPG/SVG 从 Git 索引移除，但保留本地文件，不删除本机文件。
   - 在 `.gitignore` 中永久排除真实收款码文件。
   - 公开仓库只保留配置说明，不包含可收款图片。

4. 增加发布门禁：
   - 新增提交前敏感信息扫描脚本，检查已暂存文件中的高风险 Token、私钥、真实 SMTP 密码和被禁止跟踪的路径。
   - 更新“更新到 GitHub”脚本，在 `git add` 和 `git push` 前执行扫描。

5. 暂存与验证：
   - 暂存当前项目快照，包括用户已有修改、功能代码、测试脚本和结项文档。
   - 不恢复用户已经删除的旧 README 和 vendor 文件。
   - 检查暂存文件清单、二进制文件、敏感路径和高风险字符串。
   - 运行核心语法检查和与安全修改直接相关的回归。

6. 提交与推送：
   - 创建一次结项安全发布提交。
   - 推送到 `origin/main`。
   - 通过 GitHub API 验证当前分支不再包含 `.env`、SMTP 配置、收款码文件和真实管理员邮箱。

## 三、远程历史处理选项

### 选项 A：只清理当前版本并普通推送

优点：保留现有提交历史，不影响已有克隆。  
限制：旧提交历史中仍可能访问管理员邮箱和收款码；不能称为彻底清除已经公开的内容。

### 选项 B：清理当前版本并重建公开主分支历史

优点：`main` 历史只保留脱敏后的结项快照，普通浏览不再出现旧收款码和管理员邮箱。  
影响：需要对 `main` 执行带租约的强制推送；已有克隆需要重新同步。GitHub 缓存、已知旧提交 SHA 或第三方镜像仍可能保留历史副本，因此真实凭据仍应轮换。

建议选择 **选项 B**，因为仓库是公开仓库，且敏感资源已经存在于当前远程版本。API Key 和 SMTP 密码当前没有被跟踪，但仍应保持 `.env`/Secret 隔离，并在怀疑曾公开时执行轮换。

## 四、不执行的操作

- 不上传 `.env` 或 `docs/SMTP配置.txt`。
- 不打印或读取展示 API Key、SMTP 密码、验证码或 Cloudflare Secret 值。
- 不修改 D1 用户数据。
- 不部署 Cloudflare Worker。
- 不删除本地微信收款码文件。
- 不擅自创建新 GitHub 仓库，因为目标仓库已经存在。

## 五、置信度评估

对当前工作区可以形成无 API Key、无 SMTP 密码、无私钥的公开提交的置信度：**0.98**。

对不重写历史即可“彻底消除既有公开信息”的置信度：**0.20**。若用户要求彻底清理当前 GitHub 主分支，应选择历史重建，并理解互联网缓存无法完全撤回。
