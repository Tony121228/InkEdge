# InkEdge 当前项目总览与交接文档更新计划

## 目标

整理一份面向后续开发的当前项目全景说明，并同步更新现有 `README_AGENT_HANDOFF.md`，使后续开发人员能够快速理解产品用途、用户流程、系统架构、核心代码、数据模型、AI 调用、部署方式、测试入口、当前进度和已知风险。

## 信息优先级

1. 当前源码和配置用于确认实际架构、目录、路由、数据结构和运行方式。
2. 2026-10-06 最新报告用于确认当前完成状态、测试边界和未验收事项。
3. 最新报告未覆盖的功能，才从较早报告补充。
4. 新旧报告冲突时采用最新报告。
5. 用户最新补充作为当前状态记录：参考稿真实模式质量问题已经进行一定修改，但尚不能仅据此标记为完全修复；需要在新后端进程和真实模型下重新验收。

## 计划产物

### 1. 新建当前项目全景文档

保存到 `docs/`，不覆盖历史文档。内容包括：

- 产品定位、目标用户、解决的问题和明确边界。
- 主要用户入口与完整业务流程。
- 技术栈、运行形态和整体架构。
- 根目录、`public/`、`lib/`、`scripts/`、`migrations/`、`docs/`、`test/` 的职责。
- 前端页面、状态和交互组织方式。
- 后端路由分组、主要服务流程和错误处理。
- 本地 JSON 状态与 Cloudflare D1 状态模型。
- 作文构思、体检、局部修改、参考对照、7 天训练、素材库、能力诊断、成长记录、账号和算力的调用链。
- DeepSeek 模型配置、结构化输出、事实边界和降级策略。
- 本地运行、Cloudflare Worker 部署和环境变量。
- 自动测试、浏览器测试、真实 AI 测试和报告规则。
- 当前已完成、部分完成、未验收和待调优事项。
- 后续开发常见需求对应的修改入口。
- 风险、开发禁忌和交接检查清单。

### 2. 更新 `README_AGENT_HANDOFF.md`

- 保留仍正确的历史架构说明。
- 修正已经过时的描述、路由、页面入口、测试命令和模块职责。
- 增加最新功能：新导航、参考对照、素材智能分类、成长时间线、7 天训练工作台等。
- 增加“参考稿真实模式质量已修改、待新进程真实复测”的最新状态。
- 增加指向新全景文档和最新完成进度综合报告的阅读入口。

## 核验步骤

1. 枚举项目源码和配置，不使用 Git 历史检索。
2. 从 `server.js` 提取当前路由、状态集合、模型调用和静态页面入口。
3. 从 `public/` 和 `lib/` 提取页面职责及业务模块职责。
4. 从 `package.json` 提取当前测试命令。
5. 从最新报告向旧报告回溯补齐状态。
6. 完成文档后检查文件存在、章节完整、内部路径有效和 Markdown 结构。
7. 不运行真实 AI、不启动项目、不部署、不修改业务代码。

## 输出边界

- 本轮只更新文档，不修改程序行为。
- 不把“已修改”写成“已通过真实验收”。
- 不覆盖现有报告；新文档独立保存。
- 不使用子智能体。

## 置信度

计划置信度：0.96。当前任务目标和输出范围明确；主要不确定性是 `server.js` 体量较大，需要以结构化提取方式核对路由和数据模型，避免沿用旧交接文档中的过时信息。
