# 作文修改流程与参考对照上下文调整计划

## 目标

根据浏览器批注调整作文修改页和参考对照流程：体检完成前不能生成局部修改建议；局部修改按钮放到“优先问题”卡片之后；参考对照入口只保留在局部修改建议结果之后；参考改写模型必须同时收到并使用两类修改依据：局部修改建议，以及体检报告“优先问题”卡片中报告的作文问题。

## 现状判断

- `public/app.html` 当前在修改表单底部静态显示 `#suggestBtn`，导致未体检时也可点击。
- `public/app.js` 当前 `suggestionDemo()` 会重新创建会话并重新执行体检，然后生成局部建议，应该改为复用已完成体检的会话和诊断结果。
- `renderBackendDiagnostic()` 当前把“参考对照”放在体检报告卡片中，需要移除。
- `suggestionDemo()` 当前把“参考对照”放在局部修改建议卡片中，这里应保留并作为唯一入口。
- `server.js` 当前参考改写已经从保存的 `diagnostic` 中带入 `priorityIssues`，但计划中将把这条链路显式化：增加顶层 `priorityIssues` 上下文、明确提示词约束，并用测试证明模型输入中同时存在两类依据，避免模型只关注局部建议。

## 实施步骤

1. 前端状态和渲染
   - 增加作文修改会话上下文，保存 `sessionId`、`diagnosticId`、原文、体检结果和用户修改目标。
   - 删除修改表单底部的静态局部建议按钮。
   - 体检成功后，在“优先问题”卡片下方渲染“生成局部修改建议”按钮并绑定事件。
   - 体检失败或重置时清空会话上下文和按钮。
   - 局部建议流程复用当前体检会话和诊断，不重新调用体检接口。
   - 删除体检报告卡片内的“参考对照”按钮。
   - 只在局部修改建议卡片下方保留“参考对照”按钮。

2. 参考对照请求上下文（核心要求）
   - 体检报告完成后，保存完整诊断上下文，至少包括 `overallComment`、`priorityIssues`、`highlightedSegments` 和 `suggestedRevisionPath`。
   - 局部修改建议生成后，参考对照上下文必须同时保存：`revisionSuggestion`、`revisionSuggestionText` 和体检报告的 `priorityIssues`。
   - 参考对照页请求体显式传递 `priorityIssues`，不能只传局部修改建议。
   - 服务端重新校验当前会话中的诊断结果，并在参考改写模型 `input` 中同时放入：
     - `revisionSuggestionText`：局部修改建议的具体执行要求；
     - `revisionSuggestion`：局部修改建议的思路、示范和学生行动；
     - `priorityIssues`：体检报告优先问题卡片中报告的问题；
     - `diagnostic`：体检总评、重点片段和修改路径。
   - 提示词必须要求模型先落实局部修改建议，再逐项参考 `priorityIssues` 改进作文中对应的问题；不能只复述建议，也不能忽略优先问题卡片。
   - 参考稿真实模式不设置原文事实边界限制，允许模型改写或重组原文中的事件、人物、细节、结构和表达；只保留 JSON 输出字段和 `changes` 说明结构。
   - 继续保留原文照搬拒绝、实质差异校验和事实核对边界。

3. 回归测试
   - 更新前端静态测试：按钮不在静态修改表单操作区，体检结果和优先问题卡片后存在按钮，参考对照入口只在建议结果中存在。
   - 更新参考对照 API 测试：断言模型输入顶层包含 `priorityIssues`，内容与体检报告优先问题卡片一致，并断言提示词要求模型使用这些问题。
   - 新增或调整最小回归断言，覆盖“未体检不能生成局部建议”和“建议流程不重复体检”。
   - 执行相关语法检查和测试。

4. 报告和进程清理
   - 如测试启动服务，测试结束关闭服务并清理临时状态文件。
   - 新增编号测试记录到 `docs/reports/`，不覆盖旧报告。

## 验收标准

- 打开“作文修改”页时看不到可直接点击的局部修改按钮。
- 点击“生成体检报告”并成功返回后，“优先问题”卡片末尾出现局部修改按钮。
- 局部修改按钮使用已有诊断会话，不重复发送体检请求。
- 体检结果卡片不再显示参考对照按钮。
- 局部修改建议结果卡片显示参考对照按钮并能进入参考对照页。
- 参考改写模型输入同时包含局部建议和体检 `priorityIssues`。
- `priorityIssues` 的标题、问题说明和修改建议来自当前作文体检结果，不是重新生成的泛化问题，也不是只来自局部修改建议。
   - 参考改写允许改变事件、人物和细节，并且仍能返回结构化正文和 `changes`；无效结果保护不退化。

## 置信度

计划置信度：0.95。现有代码入口和用户要求已经明确；主要风险是前端当前流程把会话创建和体检放在局部建议函数内部，需要小心处理 API 失败、重置和离线演示状态。
