# 登录注册界面照搬参考项目冒烟测试报告-1

## 1. 本轮目标

按照“你像AI吗”文本检测反测站的现有实现，复现墨锋 InkEdge 的邮箱验证码登录/注册界面和交互，不新增第二套认证协议，也不新建重复的 Cloudflare D1。

## 2. 代码复用与调整

- 参考项目的 `public/account.js` 与当前项目内容一致，账号页登录弹窗结构也一致。
- 当前项目主工作台原本只有单行游客按钮，本轮改为参考项目的双行账号按钮：显示用户名称，以及“点击登录”“试用额度”或“算力余额”。
- 主工作台继续使用邮箱验证码接口：`/api/auth/send-code`、`/api/auth/verify-code`、`/api/auth/logout`。
- 移除页面中空的 vendor auth 占位脚本挂载，避免与原生登录逻辑重复响应点击。
- 兼容当前项目游客接口返回的 `authenticated: false` 和 `role: guest`，避免游客被误显示为“算力 undefined”或进入账号内容区。

## 3. Cloudflare D1 检查

已通过 Wrangler 只读检查当前登录账户：

- 存在 `inkedge-state`，对应当前项目 `wrangler.jsonc` 的 `APP_STATE_DB` 绑定。
- 存在参考项目的 `ai-text-detector-state`，不作为墨锋项目账号库使用。
- `inkedge-state` 已有 `app_state_records`、`security_rate_limits` 和 D1 迁移表。
- `app_state_records` 中已有用户和作文业务集合记录。本轮只读取表结构和集合计数，没有读取邮箱、正文、验证码或其他 payload，也没有执行写入。

结论：直接复用现有 `inkedge-state`，不创建新 D1，不覆盖现有数据。

## 4. 验证结果

| 验证项 | 结果 |
|---|---|
| `node --check public/auth.js` | 通过 |
| `node --check public/account.js` | 通过 |
| `node scripts/auth-ui-copy.test.js` | 通过 |
| 工作台真实浏览器检查 | 通过：游客状态正确，弹窗可打开，包含邮箱和验证码输入框 |
| 账号页真实浏览器检查 | 通过：游客显示登录提示，登录/注册弹窗可打开 |
| `npx wrangler whoami` | 通过，已登录并具备 D1 读写权限 |
| `npx wrangler d1 list` | 通过，发现 `inkedge-state` 和 `ai-text-detector-state` |
| `npx wrangler d1 info inkedge-state` | 通过，远端数据库可访问 |

已有的 `app-apple-theme-ui.test.js` 在历史“我写完了”导航步骤超时，该失败发生在登录入口检查之前，属于现有工作台导航测试与当前页面结构不一致；本轮已用独立真实浏览器检查覆盖登录入口和弹窗，不将该旧测试失败归因于登录改动。

## 5. 尚未验证

本地环境未执行真实 SMTP 验证码发送，因此未完成真实邮箱收码、验证码登录和注册奖励的端到端验收。需要配置测试 SMTP 或使用已有测试邮箱后再验证，不应在报告中伪造登录成功结果。

## 6. 置信度评估

登录/注册界面复用和游客显示逻辑的置信度：**0.96**。真实邮箱验证码投递、Cloudflare Worker 生产 Cookie 和远端登录链路尚未完成端到端验收，相关置信度：**0.78**。
