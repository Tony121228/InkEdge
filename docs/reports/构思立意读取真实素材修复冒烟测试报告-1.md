# 构思立意读取真实素材修复冒烟测试报告-1

## 检查日期与环境

- 日期：2026-09-06
- 项目目录：`D:/tony/黑客松项目`
- 检查范围：“我还没写”板块中“生成构思建议”生成 3 个立意方向时是否读取“我想到的一点真实素材”。

## 问题表现

用户在“我想到的一点真实素材”文本框中输入素材后，点击“生成构思建议”，生成的立意方向表现得像只参考了作文题目，没有明显围绕用户输入的真实素材展开。

## 根因判断

根因是前后端数据链路不完整：

- 前端 `buildOutlineDemo()` 读取了素材输入框，但创建会话时只提交了题目、年级、文体。
- 前端调用题目分析接口时也只传了题目、年级、文体，没有把素材传给“题目理解与立意建议”模型调用。
- 后端创建作文会话时未保存初始素材字段。
- 后端题目分析接口构造模型输入时未包含初始素材。
- 本地兜底 `buildTopicAnalysis()` 也只根据题目推断主题，未根据素材调整立意方向。

## 修复内容

- 前端创建 brainstorm 会话时新增提交 `initialMaterial`。
- 前端调用 `analyzeTopic()` 时新增提交 `initialMaterial` 和 `existingMaterials`。
- 后端新增初始素材标准化处理，兼容字符串、数组和对象输入。
- 后端创建作文会话时保存 `initialMaterial`。
- 后端题目分析接口把 `initialMaterial` 放入 DeepSeek 提示词输入。
- 本地兜底题目分析逻辑在有素材时生成更贴近素材的 3 个立意方向。

## 验证结果

### 红灯复现

- `npm run test:essay-guidance` 曾失败，失败点为创建会话返回中 `initialMaterial` 为 `undefined`。
- `npm run test:short-guidance-frontend` 曾失败，失败点为前端 `buildOutlineDemo()` 未在创建会话和题目分析请求中提交 `initialMaterial`。

### 修复后测试

- `node --check server.js`：通过。
- `node --check lib/essay-guidance.js`：通过。
- `node --check public/app.js`：通过。
- `npm run test:essay-guidance`：通过。
- `npm run test:short-guidance-frontend`：通过。
- `npm run test:essay-guidance-missing-key`：通过。
- `npm run test:training-plan-7d`：通过。
- `npm run test:long-term-ability`：通过。

## 结论

“我还没写”的构思建议链路已能把用户在“我想到的一点真实素材”中输入的内容传递到会话、题目分析接口和模型提示词中。后续生成 3 个立意方向时，模型侧具备参考用户真实素材的输入条件；本地兜底模式也会根据素材生成更贴近的方向。

## 风险与后续建议

- 若 DeepSeek 返回内容仍显得空泛，下一步应继续加强“题目理解与立意建议”的提示词约束，要求每个立意方向必须引用或改写用户素材中的一个具体细节。
- 建议部署后在线上用一条包含具体素材的输入做一次真实模型冒烟，确认线上 Secret、Worker 版本和前端静态资源均已更新。
