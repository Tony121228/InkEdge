# 作文修改流程与参考对照上下文调整冒烟测试报告-1

## 1. 测试目的

验证最新需求对应的作文修改流程是否生效：

1. 作文体检完成后，局部修改建议入口才出现，并位于优先问题卡片下方。
2. 体检报告卡片不再提前显示“参考对照”入口。
3. 参考对照入口只从局部修改建议结果进入。
4. 体检报告生成的 `priorityIssues` 与局部修改建议一起传给参考稿模型。
5. 参考稿模型不再受到原文事实边界限制，可以改写和重组事件、人物、细节、结构和表达，避免只做标点或少量词语替换。
6. 普通局部修改模式原有的可补充合理描写行为不被误改；只有显式传入 `keepFactsStrict=true` 时才启用严格事实约束。

## 4. 关键检查结论

### 4.1 参考稿上下文已补齐

参考稿模型收到的输入同时包含：

- `revisionSuggestionText`
- `revisionSuggestion`
- `priorityIssues`
- `diagnostic`
- `revisionGoal`
- `revisionDepth`

其中顶层 `priorityIssues` 由当前作文体检结果生成，并在测试中验证与 `diagnostic.priorityIssues` 一致。

### 4.2 参考稿事实限制已移除

参考改写请求不再发送 `revisionBoundary`，提示词明确允许自由改写和重组事件、人物、细节、结构和表达，并要求产生清楚可见的实质变化。输出仍保留 `revisedText` 和 `changes` 结构，这是前端渲染和修改说明所需的接口格式，不属于原文事实限制。

### 4.3 两条模式未混淆

“参考稿真实模式”与“局部修改建议严格事实模式”是两个不同入口。当前只对局部修改建议的 `keepFactsStrict=true` 追加严格事实约束，参考稿分支不会继承该限制；普通局部修改仍允许合理描写，并要求通过 `factCheck.addedDetails` 提醒核对。

## 5. 未覆盖范围与后续风险

本次自动化测试使用模型桩验证请求结构、提示词和前端流程，没有在真实模型上验收改写质量。由于本地环境未配置可用的模型密钥，本次未执行真实参考稿生成，也未能用真实作文确认改写幅度是否达到预期。后续应使用真实模型重新打开 `reference-comparison.html`，确认参考稿不再只进行标点或个别词语替换，并核对 `changes` 与正文实际改动一致。

本次启动的本地服务已在验证结束后关闭。
