# 浏览器批注 UI 与作文修改闭环开发计划

> **For agentic workers:** 使用子代理分任务开发；测试脚本编写、运行和结果整理必须交给子代理。所有任务按测试先行执行，不部署线上环境。

**Goal:** 完成用户在 `/app` 页面标注的 21 项界面和功能修改，降低构思结果的信息负担，并补齐“原文与 AI 参考改写并排对照”的完整功能。

**Architecture:** 保留现有单页工作台和作文会话 API。静态文案、表单联动、构思结果展示继续由 `public/app.html`、`public/app.js`、`public/styles.css` 负责；“参考对照”使用独立页面和独立后端接口，接收当前作文会话、体检结果和修改建议，生成严格保持事实边界的参考改写。补充素材通过现有题组上下文进入写作引导，不与素材库或长期训练混用。

**Tech Stack:** Node.js、Express、静态 HTML/CSS/JavaScript、DeepSeek Chat API、Playwright。

**Spec:** 用户 2026-09-27 在浏览器中的 21 条批注。

## Global Constraints

- 不改变“先选立意，再点击素材追问”的既有顺序。
- 不把 DeepSeek Key 暴露到前端或报告。
- “参考改写”不得新增原文没有的人物、地点、时间、事件、结果、对话、心理变化或关键物件。
- 新页面必须同时支持桌面双栏和移动端上下排列。
- 不部署；开发完成后由子代理执行本地自动测试、真实 AI 冒烟和视觉检查。
- 测试报告只保存一份编号 Markdown 到 `docs/reports/`。

## Review Focus

- 修改目标或修改深度选择“其他”时，未填写自定义内容必须阻止请求并给出中文提示。
- 用户在补充素材后重新生成写作引导，旧题组、立意和补充内容不能串到别的会话。
- 提纲树在长标题、长节点和移动端下不能横向溢出或遮挡。
- 十分制分数的数值、分母和进度条比例必须一致，例如 `7/10` 对应 70%。
- 参考改写页面刷新、缺少会话数据、模型失败时必须显示可操作错误，不出现空白页。

## 一、批注对应设计

### 1. 导航和页面文案

- 侧栏：`总览` 改为 `导航`，`我还没写` 改为 `作文构思`，`我写完了` 改为 `作文修改`，`训练计划` 改为 `写作计划`，`成长` 改为 `成长记录`。
- 首屏 eyebrow：`作文训练工作台` 改为 `写作训练工作台`。
- 构思标题：`我还没写，帮我构思` 改为 `文章构思`。
- 修改标题：`我写完了，帮我修改` 改为 `修改作文`。
- 构思表单：`作文题目` 改为 `作文标题`，文体新增 `散文`。
- 总览入口卡片同步使用新名称，内部 `data-view` 保持不变，避免破坏路由。

### 2. 立意卡与写作引导

- 立意卡不再显示 `继续追问` 和 `风险提醒`；后端字段仍保留，用于模型生成和质量校验。
- 提纲改为简洁叉状树：根节点展示标题/主题，四个分支只展示段落角色与一句结构摘要；不再在提纲树中展开详细对象、细节、心理、衔接和自查。
- 提纲树使用 CSS 连接线、进入动画和选中高亮；移动端改为纵向分支，禁止横向滚动。
- 全部结果展示移除 `自查` 板块。
- `必须写入` 更名为 `核心元素`。
- 每个段落提示卡使用原生 `details/summary` 或等价无障碍折叠结构；默认展开第一段，其余默认收起，文本框始终属于对应段落。

### 3. 继续回答素材

- `missingMaterialQuestions` 从写作引导末尾移到“回答素材追问”板块末尾。
- 展示缺失问题列表和 `继续回答` 按钮；点击后展开一个补充素材文本框及 `更新写作引导` 按钮。
- 前端把补充文本作为 `additionalMaterial` 连同当前 `questionSetId`、`selectedAngleId` 和原有答案再次提交。
- 后端验证补充文本属于当前会话和题组，加入事实来源后重新生成提纲与段落提示，并持久化到当前会话；空文本不得请求模型。

### 4. 修改表单和十分制评分

- 修改目标、修改深度都新增 `其他` 选项；选择后在对应下拉框下方显示自定义输入框，切换回预设项时隐藏并清空。
- 体检分数卡按十分制渲染：显示 `x/10`，进度条宽度为 `x * 10%`；能力画像等百分制组件不受影响。

### 5. 参考对照页面

- 作文体检或局部建议完成后显示 `参考对照` 按钮。
- 点击按钮把 `sessionId`、原文、诊断 ID、修改目标和建议 ID/内容写入 `sessionStorage`，并打开 `/reference-comparison.html`。
- 新增 `POST /api/v1/essay-sessions/:sessionId/reference-rewrite`：根据原文、诊断和修改建议生成完整参考改写，返回 `originalText`、`revisedText`、`appliedChanges`、`factCheck`。
- 新页面左侧原文、右侧参考改写；移动端上下排列。提供返回工作台、重新生成和复制参考稿按钮，并明确标注“参考稿，不替代学生定稿”。

## 三、完成标准

- 21 条批注均能对应到可见 UI 或可执行功能。
- “作文构思”路径不因 UI 精简而丢失立意选择、素材追问、写作引导和分段写作能力。
- 补充素材可以真实影响重新生成的提纲与段落提示。
- 作文诊断分数按十分制正确展示。
- 参考对照页能用真实 AI 生成保持事实边界的完整参考稿，并与原文并排显示。
- 自动测试和真实 AI 冒烟通过；无未捕获前端异常；本地测试进程已关闭。

## 四、置信度评估

置信度：0.91

依据：绝大多数批注可在现有静态前端渲染层内完成；项目已有作文会话、体检、局部建议、API 客户端和 DeepSeek 调用基础。主要不确定性在“继续回答”对写作引导的二次生成，以及完整参考改写的事实边界，需要通过新后端契约、结构化输出和真实 AI 冒烟收敛。
