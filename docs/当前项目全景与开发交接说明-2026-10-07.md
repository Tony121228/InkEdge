# InkEdge 当前项目全景与开发交接说明

更新时间：2026-10-07  
项目：墨锋 InkEdge

## 1. 这是什么项目

InkEdge 是一个面向中小学生的中文作文训练工具。它的目标不是直接替学生生成一篇可以照抄的作文，而是把作文任务拆成若干个可练习的步骤：理解题目、选择立意、回忆真实素材、组织提纲、完成段落、体检问题、针对性修改，并把训练结果沉淀为后续能力记录。

项目同时保留一条“作文检测与改写”产品线，用于检测文本中的 AI 痕迹、诊断问题、生成不同安全程度的改写版本，并对事实边界、改写过程和改写后风险进行解释。

因此当前系统有两组相互关联但入口不同的能力：

| 能力组 | 主要入口 | 主要用途 |
|---|---|---|
| 作文训练工作台 | `/app.html` | 从题目、素材或草稿开始，分步骤完成作文训练 |
| 检测与改写工作台 | `/index.html` | 检测 AI 风险、诊断问题、生成改写和参考对照 |

训练工作台更偏“教学生写”；检测与改写工作台更偏“检查和编辑已有文本”。后续开发必须先判断需求属于哪条链路，避免把训练阶段模型和改写阶段模型混在一起。

## 2. 当前产品范围

### 2.1 作文构思

用户可以输入作文标题、年级、文体和已有真实素材，先得到多个立意方向，再选择一个方向，系统围绕该方向生成素材追问。用户回答追问后，系统生成提纲树和分段写作提示。每个段落提示下有输入框，用户写完后可以合并为完整草稿并进入作文修改流程。

当前导航名称已经逐步统一为：

- 导航
- 作文构思
- 作文修改
- 素材库
- 写作计划
- 成长记录

代码中仍可能存在旧变量名或旧函数名，这是兼容历史实现的内部名称，不等于用户界面仍使用旧文案。

### 2.2 作文体检

作文体检接收完整草稿，生成：

- 总体评价。
- 题目/扣题、素材具体性、结构清晰度等维度分数。
- 优先修改问题。
- 原文可疑或需要关注的片段。
- 建议修改路径。

体检结果既可以留在当前作文会话中，也可以作为局部修改和参考对照的输入。

### 2.3 局部修改

用户选择一个具体问题或目标后，系统生成：

- 问题说明。
- 修改策略。
- 示范修改。
- 学生行动建议。
- 修改目标和事实核对信息。

默认局部修改允许合理的表达补充，但前端会显示新增细节提醒；如果指定严格事实模式，后端应限制新增人物、地点、时间、事件、结果、对话、心理和关键物件。

### 2.4 参考对照

参考对照是独立页面 `public/reference-comparison.html`。它接收原文、体检结果和修改建议，让模型生成一份用于学习的参考稿，并与原文进行对照。

当前实现包括：

- 参考稿专用模型提示分支。
- 原文、体检报告优先问题、局部修改建议一起传给模型。
- 参考稿真实模式允许自由改写或重组事件、人物、细节、结构和表达，不设置原文事实边界限制。
- `addedDetails` 和 `coreFactsPreserved` 元数据。
- “请核对补充细节”提示。
- 原文完全照搬拒绝机制。
- 只改标点或实质差异不足时拒绝返回成功。

最新状态必须这样理解：用户已经对“参考稿真实模式质量”进行了进一步修改，代码侧已有假模型回归和实质差异校验记录；但截至本交接文档生成时，仍不能把它写成真实模型已经彻底解决。之前一次真实生成主要只改标点和衔接，且运行中的本地服务可能没有重载新 `server.js`。后续开发第一步应重启本地服务，用真实作文重新验证，并区分“源码已修改”和“真实模型效果已通过”。

### 2.5 7 天写作计划

训练计划固定为 7 天、单篇作文训练工作台。阶段顺序如下：

| 阶段 ID | 用户看到的内容 | 产物 |
|---|---|---|
| `topic_angle` | 选择立意 | `possibleAngles` |
| `material_questions` | 回答素材追问 | `questions`、`answers` |
| `outline_tree` | 查看文章结构 | `outlineTree` |
| `paragraph_guides` | 查看各段写作提示 | `paragraphGuides` |
| `paragraph_drafting` | 输入各段草稿并合并 | `paragraphDrafts`、`mergedDraft`、反馈 |
| `draft_diagnosis` | 体检完整草稿 | `overallComment`、`dimensionScores`、`priorityIssues` |
| `revision_reflection` | 输入修改稿并复盘 | `summary`、`learnedSkills`、下一步训练重点 |

服务端保存每个阶段输入和产物，更新 `completedStageIds`、当前阶段和计划状态。完成第 7 天后，计划进入完成状态。

### 2.6 素材库

素材库的设计方向是“只输入真实素材”。用户不必先填写标题、分类和适用题目，服务端会调用写作辅导模型生成：

- 素材标题。
- 场景和分类。
- 适合的作文题目。
- 题目适配理由。
- 关键词。
- 可展开的写作角度。

模型失败时，服务端仍会生成一个本地结构化卡片，但必须标记 `localFallback`，不能把本地结果冒充真实模型结果。

### 2.7 能力诊断和成长记录

能力模块由 `lib/long-term-ability.js` 负责，主要概念包括：

- 初始能力测评。
- 八个能力维度。
- 当前阶段、优势、短板和训练焦点。
- 训练任务提交与反馈。
- 复盘后的能力画像更新。
- 成长时间线、徽章和下一步建议。

成长时间线由服务端根据能力画像、作文体检、训练计划、训练提交和复盘记录聚合生成，而不是固定返回空数组。新功能开发应优先复用 `buildGrowthTimelineForUser()` 和 `lib/long-term-ability.js`，不要重新建立一套独立成长数据。

### 2.8 账号、算力和管理员

账号体系支持：

- 邮箱验证码登录/注册。
- 会话 Cookie。
- 用户资料。
- 登录用户算力余额。
- 算力流水和充值说明。
- 管理员用户列表、手动增减算力、用户名修改和普通用户删除。
- 游客临时 IP 额度查看。

管理员相关接口只能由管理员调用。游客 IP 管理后台是只读的，历史记录只有哈希时必须显示 `IPhash`，不能伪装成真实 IP。

## 3. 技术架构

### 3.1 技术栈

- 后端：Node.js + Express 5。
- 前端：静态 HTML、CSS、原生 JavaScript，无 React/Vue 构建链。
- AI：OpenAI-compatible Chat Completions 接口，当前默认 DeepSeek。
- 本地状态：`data/app-state.json`。
- Cloudflare 状态：D1 表 `app_state_records` 和 `security_rate_limits`。
- 浏览器验证：Playwright。
- 部署：Cloudflare Worker + `cloudflare:node` 的 `httpServerHandler`；另有 Render 配置说明。

### 3.2 请求处理总览

```text
浏览器静态页面
  -> public/*.js / public/api-client.js
  -> Express 路由（server.js）
  -> 会话、权限、额度与状态读取
  -> 业务模块（lib/*.js）
  -> DeepSeek-compatible 模型（需要 AI_API_KEY）
  -> 结构化结果归一化、事实校验、状态写回
  -> JSON 响应
  -> 页面状态更新和结果渲染
```

检测与改写工作台还存在一条后台任务链：

```text
POST /api/rewrite-tasks
  -> 创建任务并返回 taskId
  -> 后台检测阶段
  -> 达到阈值后进入改写阶段
  -> 前端轮询 /api/rewrite-tasks/:id
  -> 渲染检测、改写、事实审计、编辑计划和失败原因
```

训练工作台使用另一条同步阶段链：

```text
创建作文会话或 7 天计划
  -> 运行当前阶段
  -> 保存 stageInputs 和 stage artifact
  -> 返回当前进度、下一阶段和 uiHints
  -> 用户确认后进入下一阶段
```

### 3.3 运行形态

本地运行时，`server.js` 读取 `.env`，以 `PORT` 启动 Express，并从 `data/app-state.json` 读取状态。

Cloudflare Worker 运行时，`worker.mjs`：

1. 从 Cloudflare `env` 注入 `process.env`。
2. 设置 `globalThis.CLOUDFLARE_ENV`。
3. 动态加载 `server.js`。
4. 使用 Node HTTP server 和 `httpServerHandler` 暴露 Express。

Worker 环境下，服务端不把状态写入本地文件，而是通过 D1 适配层加载和持久化 `STATE_COLLECTIONS` 中的集合。

## 5. 服务端状态模型

`server.js` 的 `DEFAULT_STATE` 当前包含这些集合：

| 集合 | 用途 |
|---|---|
| `users` | 登录用户、角色、算力余额、资料和时间 |
| `verificationCodes` | 邮箱验证码及过期/尝试次数 |
| `sessions` | 登录会话和最近活跃时间 |
| `guestUsages` | 旧游客 Cookie 额度兼容记录 |
| `guestIpUsages` | 游客 IP/IP-hash 额度和最后访问时间 |
| `powerLedger` | 赠送、充值、消耗和管理员调整流水 |
| `rechargeOrders` | 充值订单状态 |
| `rewriteTasks` | 检测/改写后台任务及阶段结果 |
| `authRateLimits` | 登录和验证码速率限制 |
| `essaySessions` | 作文会话、题目、文体、素材、当前状态和选定立意 |
| `essayDiagnostics` | 作文体检结果 |
| `essayMaterials` | 素材卡和自动分类结果 |
| `essayReflections` | 作文复盘结果 |
| `essayGuides` | 提纲、段落提示和引导结果 |
| `trainingPlans` | 7 天训练计划、阶段输入、阶段产物和进度 |
| `trainingTaskSubmissions` | 训练任务提交和反馈 |

本地模式由 `loadState()` / `saveState()` 读写 JSON。Cloudflare 模式由 `loadCloudState()` / `persistCloudState()` / `flushCloudState()` 与 D1 的 `app_state_records` 同步。D1 通过 `(collection, id)` 作为主键，每个集合项以 JSON payload 存储。

### 会话归属原则

作文会话必须通过 `assertOwnedEssaySession()` 校验当前用户或当前学生 ID。后续新增会话相关接口必须使用同一归属检查，不能只按 `sessionId` 查询。

### 额度原则

- 登录用户：从 `powerBalance` 扣除，流水写入 `powerLedger`。
- 未登录游客：优先使用临时 IP 记录，并兼容旧 Cookie 记录。
- 检测和改写分别估算成本。
- 测试必须使用临时 `APP_DATA_DIR`，不能污染正式 `data/app-state.json`。

- `POST /api/train`：训练规则库，Cloudflare 生产环境需谨慎使用。
- `POST /api/track`：埋点事件。
- `GET /api/debug/upstream`：上游 AI 网络诊断。
- `GET /health`：健康检查。

## 7. AI 调用和结果处理原则

### 7.1 模型配置

本地环境变量来自 `.env.example`：

- `AI_API_BASE_URL`
- `AI_API_KEY`
- `AI_DETECT_MODEL`
- `AI_REWRITE_MODEL`
- `AI_GUIDANCE_MODEL`

写作辅导建议单独使用 `AI_GUIDANCE_MODEL`，不要默认复用改写模型。当前 Cloudflare 配置默认三个模型都为 `deepseek-chat`。

### 7.2 统一模型调用

`server.js` 的 `callModel()` 负责：

- 检查 API Key。
- 设置模型、温度、最大 token 和 `response_format`。
- 计算剩余超时。
- 执行有限重试。
- 解析上游响应。
- 记录 token 使用量。

写作辅导由 `callEssayGuidanceModel()` 进一步绑定任务名、输入、输出合同和模型元数据。模型结果必须经过各业务的 normalize 函数，不能把未经校验的模型 JSON 直接交给前端。

### 7.3 写作辅导调用链

```text
topic-analysis
  -> 题目、年级、文体、真实素材
  -> 立意方向

material-questions
  -> 已选立意、真实素材
  -> 追问问题

guided-writing
  -> 已选立意、回答、补充素材
  -> outlineTree + paragraphGuides + studentTask

diagnose
  -> draftText
  -> overallComment + dimensionScores + priorityIssues + highlightedSegments

revision-suggestions
  -> 诊断问题、原文、修改目标、事实模式
  -> issueExplanation + revisionStrategy + exampleRevision + studentAction

reference-rewrite
  -> 原文、体检优先问题、局部修改建议
  -> revisedText + changes + factCheck
```

### 7.4 检测和改写调用链

检测先由本地 `analyzeAiSignals()` 计算规则命中、文本画像和风险分，再调用模型复核，最后由 `mergeDetection()` 合并结果。命中 `REWRITE_TRIGGER_THRESHOLD` 后，后台任务进入改写阶段。

改写阶段依次涉及：

1. `chooseRewriteMode()` 选择强力、平衡或保守模式。
2. `getRewriteModePolicy()` 读取模式策略。
3. `buildVoiceProfile()` 生成作者风格画像。
4. `buildFactInventory()` 提取原文事实。
5. `buildLocalEditPlan()` 生成编辑计划。
6. `buildExecutableEditPlan()` 过滤为可执行动作。
7. `executeRewriteWithPlan()` 调用模型并处理候选。
8. `auditRewriteFacts()` 检查新增事实。
9. `rankCandidates()` 结合保留度、长度、段落覆盖和改写后 AI 率排序。
10. 服务端生成统计、前后对比、删除/压缩摘要和失败原因。

三种模式的产品边界：

| 模式 | 事实审计 | 适用方向 |
|---|---|---|
| 强力 | 关闭，可为 `null` | 优先降低模板感和 AI 痕迹 |
| 平衡 | 作为提醒，不应强阻断 | 降低 AI 味并尽量保留原意 |
| 保守 | 严格审计，必要时阻断或本地降级 | 尽量不改变事实 |

强力模式的 `factAudit = null` 和 `factInventory = null` 是设计，不是缺字段；前端渲染必须兼容 null。

## 8. 失败、降级和数据安全边界

### 8.1 模型失败

写作辅导接口通过 `v1ModelCatch()` 统一返回可识别的失败码。缺少 Key、上游不可用、超时、模型 JSON 不合法都应保留明确错误原因，不要静默返回看起来像模型成功的内容。

### 8.2 本地降级

本地/保守降级只能删除空泛句、压缩模板表达并保留原文事实，不得：

- 补写新的生活经历。
- 把作者样本事实迁移到当前作文。
- 承担真实风格校准。
- 混入真实模型改写成功率统计。

### 8.3 参考稿生成边界

参考稿真实模式与普通局部修改的严格事实模式不同：它允许模型自由改写或重组原文中的事件、人物、细节、结构和表达。模型仍需返回结构化 `revisedText` 和 `changes`，但不再要求保留原文事实，也不再要求输出新增事实核对清单。完全照搬或只做标点级变化不应被当作有效参考稿。

当前参考稿真实质量状态：用户已进行一定修改；假模型回归和差异门槛已经有记录，但真实模型效果必须在重启服务后重新验证。

### 8.4 会话和密钥

- 所有作文会话读取和写入都要校验归属。
- `.env`、D1 Secret 和本地状态不得提交。
- 报告和日志不得打印真实 API Key、验证码、SMTP 密码或用户隐私。
- 测试状态必须隔离，结束后关闭测试进程并删除临时状态文件；只允许逐个删除文件，不能删除文件夹。
